# みちのーと｜放課後のあゆみ — 記録・共有・個別支援計画デモ

放課後等デイサービスの日々の記録を、職員記録・保護者への共有・次期個別支援計画の「見直し原案」へつなぐブラウザアプリです。介護向け画面モック「ケアのあゆみ」の記録・家族共有導線を、放課後等デイ向けに再設計して「みちのーと」へ統合しています。

すべて架空のAさん（小学4年生）のデモデータです。診断名は設定していません。元の参考画像に写る実在人物の情報・文章・署名・印影はアプリへ転載していません。

## 起動

外部ライブラリやAPIキーは不要です。プロジェクト直下で次を実行してください。

```bash
npm run serve
```

ブラウザで <http://localhost:4173> を開きます。

macOSでデモを行う場合は、Finderから `デモを起動.command` をダブルクリックしても起動できます。ブラウザが自動で開きます。詳しい進行は `DEMO_GUIDE.md` を参照してください。

`index.html` を直接ダブルクリックすると、ブラウザのES Modules制約で読み込めない場合があります。上記のローカルサーバーは `127.0.0.1` だけで待ち受け、アプリに必要なファイル以外（参考JPGを含む）を配信しません。

## デモで確認できること

- Aさんの2026年4〜5月、48件の日誌
- 今日の職員確認待ち、保護者共有準備、計画更新状態をまとめたワークベンチ
- ひとつの観察記録から、用途を分けた「職員記録」「保護者向け文章」のデモ下書き作成
- 下書き保存 → 職員確認 → 保護者共有の準備 → デモ共有という明示的な確認フロー
- 職員確認と保護者共有を別状態で管理し、未確認・未共有の記録を保護者画面へ出さない制御
- 「放課後のあゆみ」保護者画面の共有前プレビュー、全共有履歴の選択、デモ共有取消
- 「観察した事実 → 行った支援 → 本人の反応」の時系列確認
- 日誌の追加・編集・削除、検索、月・5領域フィルター、利用時間・記録者、CSV出力
- NotebookLMへ取り込める、内部記録と保護者向け文章を列で分離したCSV出力
- 健康・生活／運動・感覚／認知・行動／言語・コミュニケーション／人間関係・社会性の記録量
- 4つの観察指標の前半・後半比較（未評価／対象外を除く有効件数付き）
- 分析期間の指定（最大92日）と、範囲外入力時の停止
- 日誌からの個別支援計画見直し原案の作成
- 本人支援、家族支援、移行支援、地域支援・地域連携（地域支援は理由付きの「該当なし」も記録可）
- 各本人支援目標から根拠日誌への逆リンクと、日誌の追加・解除
- 作成時の日誌ID・内容・件数・期間を根拠スナップショットとして保持し、変更後は再生成まで印刷を停止
- 生活課題、責任者、5領域、6か月以内の見直し、家族・移行・地域支援の必須項目の記載チェック
- 面接 → 会議 → 作成 → 本人説明・対象版への文書同意 → 交付の工程順序チェック
- 帳票主要項目の編集、A4横の帳票プレビュー、各ページの文書識別情報・ページ番号付き印刷／PDF保存
- ブラウザ内自動保存とデモ初期化

## このデモの前提

日誌だけでは、正式な個別支援計画を完成できません。本アプリは、既存計画と2か月分の日誌を使ったモニタリングから「次期計画の見直し原案」を作る想定です。

原案の確定前に、少なくとも次が必要です。

1. 児童発達支援管理責任者による、本人・保護者への面接を含むアセスメント
2. 支援担当者等による個別支援会議
3. 本人に合う方法での説明と、意見・反応・理解状況の記録
4. 保護者への説明と文書同意
5. 保護者、該当する指定障害児相談支援事業者への交付
6. 継続的なモニタリングと、少なくとも6か月に1回の見直し

参考様式は全国一律の必須書式ではありません。本番導入前に、指定権者の条例・通知・指導監査上の運用を確認してください。

## 原案の作り方

この版は外部AIを呼び出しません。画面上の「デモ下書き」は、入力された明示情報をブラウザ内で用途別に並べ替える機能です。再現性と説明可能性を優先し、次のように整理します。

- 職員記録は「観察した事実・行った支援・本人の反応」だけをラベル付きで整理
- 保護者向け文章は、明示された家庭共有欄、または活動・本人の反応だけを使用し、内部の支援文を混ぜない
- 元記録にない日付、回数、診断、評価、因果関係を補わない
- 下書き生成だけでは保存・職員確認・共有を行わない
- 日誌本文の編集後は職員確認待ちへ戻し、保護者共有状態を自動解除

- 援助要求、切り替え、仲間とのやり取り、自己調整それぞれの「中核タグ」だけを候補化に使用
- 自動タグは「観察した事実」と「本人の反応」だけから候補化し、職員が行った支援の文面は推定根拠にしない
- 同じ中核タグが「3件以上・2場面以上・14日間以上」に満たなければ、確認不足として支援目標を自動生成しない
- ひとつの分析・原案作成に使う日誌は連続92日以内とし、長期間の記録を一括して同じ傾向とみなさない
- 件数・場面数・期間は「確認候補」の閾値にしか使わず、変化の方向、因果、有効支援を断定しない
- 数値目標・具体策を含む詳細テンプレートは、同梱のAさんデモが完全に未変更の場合だけ使用。日誌や意向を変更した場合は、原記録と面接で確定する「確認用暫定案」に自動で切り替え
- 同梱デモ以外では家族支援・移行支援・地域支援・モニタリングを自動補完せず、面接・会議に基づく入力を必須チェックで促す
- 1件の成功だけで「習得済み」と断定しない
- 成長だけでなく、疲労、騒音、予定変更などの揺らぎも残す
- 「できない」ではなく、どの条件・支援でどう変化したかを記述
- 本人支援全体で5領域を網羅（5目標へ1対1に分割しない）
- 支援目標ごとに評価方法、期限、担当、留意事項、根拠日誌を保持
- 本人・家族の意向はデモ値であり、実運用では面接内容に置換
- 診断名、性格、家庭環境を日誌から推定しない

## データ保存と個人情報

デモの入力内容は、利用中のブラウザの `localStorage` だけに保存され、外部へ送信されません。ただし、`localStorage` は本番の児童情報を保存する仕組みとして不十分です。

本番化では、認証、職務別権限、通信・保存時暗号化、監査ログ、版管理、バックアップ、保存期間、復旧・削除方針、本人・保護者への情報提供、外部共有時の同意管理が必要です。個別支援計画等の記録は、運営基準と指定権者の規定を確認し、サービス提供日から5年以上の保存に対応する想定で設計してください。元のJPG参考画像は実名・健康発達情報・受給者証番号・署名等を含むため、公開・配信しないでください。

## テスト

生成ロジックと記録共有ワークフローの自動テスト（38件）：

```bash
npm test
```

ブラウザ操作テストは `tests/e2e.test.mjs` にあります。初回のみ依存関係とChromiumを用意してから、次を実行します。テスト用サーバーの起動・終了は自動です。記録から用途別下書き、職員確認と共有の分離、共有取消、旧保存データ移行、日誌追加・保存復元、92日上限、更新後の古い計画の印刷停止と再生成、モバイル、根拠IDを含む実PDFまで確認します。

```bash
npm install
npx playwright install chromium
npm run test:e2e
```

Codexの検証環境では、`webapp-testing` の `with_server.py` からサーバーと試験を一括起動できます。

最終検証では、Chromiumの印刷機能でA4横・3ページ・タグ付きPDFを生成し、全ページのページ番号と文書識別情報、支援目標ごとの根拠日誌IDをテキスト抽出と画像化の両方で確認しています。印刷結果はブラウザとOSの設定に依存するため、本番で採用する端末構成でも受入確認してください。
